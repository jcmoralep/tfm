Standing rules baked into every task:

- **Everything is off by default.** With no configuration the pipeline, the DI graph, the pages and every existing test behave as on `main`. Each slice must keep existing tests unedited except where a task says so.
- **Lean tests.** Group same-rule cases in `[Theory]`; no reflection-shape tests; no label-by-label tests; keep rule, gate, round-trip and leak tests. Options tests also assert that **a thrown message never contains the configured secret value**.
- **Views.** CSS classes only: no `style=`, no `<script`, no new JS module, except the single documented exception in `CaptchaWidget.razor` (S2). Grep every touched razor file: `rg "style=|<script" src/RutaProducto.Web/Components`.
- **Logs.** Never log emails, recipients, subjects, bodies, tokens, links, passwords, captcha tokens, secrets or the client IP. Only request name, ids, email kind, outcome, status codes, durations, exception type (RNF-02). Every new command overrides `ToString()` so `LoggingBehavior` cannot print its content.
- **Build and test commands** (every gate): `dotnet restore --ignore-failed-sources -p:NuGetAudit=false -p:WarningsNotAsErrors=NU1507`, then `dotnet build -c Release --no-restore` (zero code warnings), then `dotnet test -c Release --no-build`. `System.Net.Mail.SmtpClient` obsolete warnings are suppressed narrowly in `SmtpEmailTransport` only, with a comment.

## Reconciliation notes (design wins; the spec was aligned in this phase)

Every item below is a divergence between `specs/authentication/spec.md` and `design.md` (or an unstated gap) found by reading both in full. The tasks above follow the design. The matching spec lines were amended in this phase; the design text rules if any spec line still disagrees.

- **R1, routes.** Spec: `/olvide-contrasena`, `/reenviar-confirmacion` ("proposals; fixed in design"). Design D17: **`/recuperar-contrasena`**, **`/confirmar-correo/reenviar`**, plus `/confirmar-correo` and `/restablecer-contrasena`, declared with `[Route(AuthenticationEndpoints.X)]` constants. Spec text and the RF-82 edit amended everywhere.
- **R2, sender seam split.** Spec: one `IEmailSender` that "sends one message" plus a queue service with a sender double. Design D9: `IEmailSender.Enqueue(EmailMessage)` (Application, sync, never blocks) is separate from `IEmailTransport.SendAsync` (Infrastructure, SMTP); `QueuedEmailSender` and `DisabledEmailSender` implement the first, `EmailDispatcher` calls the second. Scenarios "Queue returns before sending" and "Sender failure is contained" now use a transport double; the queue is bounded at 100 with `DropWrite`, the dispatcher registered only with Smtp, no retries, queued mail lost on shutdown.
- **R3, email log fields.** Spec: kinds `Confirmation`, `Reset`, `AccountExists`, user id and duration. Design D9, D10, D12: kinds `ConfirmEmail`, `AccountExists`, `ResetPassword`; failures log kind, exception type and `SmtpStatusCode`; the token service logs user id and outcome. Spec amended.
- **R4, captcha outcome and request.** Spec: `Passed`/`Failed`/`Unavailable`, request carries the remote IP, only missing/empty token is rejected without a call. Design D4: **`Rejected`** (not `Failed`), **no `remoteip`** (wrong behind the proxy until Railway-prep), blank, missing or over-2,048-character token is Rejected with no call, `VerifyAsync(string?, CancellationToken)`, `CaptchaWidgetSettings(SiteKey)`. Spec amended throughout (every `Failed` became `Rejected`). The Spanish captcha texts are not in the design; the spec's verbatim texts are kept.

The form name differs per page (`register`, `forgot`). Spec amended.
